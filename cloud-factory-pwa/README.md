# 구름 공장 운영 시뮬레이터

서버나 빌드 도구 없이 GitHub Pages에 올릴 수 있는 단일 페이지 게임입니다. 데스크톱과 모바일 브라우저에서 플레이할 수 있고, 지원 브라우저에서는 홈 화면이나 앱 목록에 설치해 실행할 수 있습니다.

## GitHub에 올리기

1. GitHub에서 저장소를 만들거나 사용할 저장소를 엽니다.
2. 이 폴더 안의 파일과 icons 폴더를 저장소의 최상위에 올립니다. 저장소 최상위에 index.html, manifest.webmanifest, sw.js, icons/가 보여야 합니다.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Build and deployment**에서 **Deploy from a branch**를 고르고, 배포할 브랜치와 **/(root)** 폴더를 선택해 저장합니다.
5. Pages가 안내하는 주소가 열리면 그 주소를 휴대폰 브라우저에서도 방문합니다. HTTPS가 활성화된 주소에서 설치와 오프라인 실행을 사용할 수 있습니다.

이 프로젝트는 GitHub Pages의 프로젝트 경로 아래에서도 작동하도록 모든 웹 앱 주소를 상대 경로로 설정했습니다.

## 휴대폰에 설치하기

- **Android:** 게시된 HTTPS 주소를 Chrome으로 열고 상단의 **앱 설치** 버튼을 누릅니다. 버튼이 보이지 않으면 브라우저 메뉴에서 **앱 설치** 또는 **홈 화면에 추가**를 선택합니다.
- **iPhone/iPad:** Safari에서 게시된 주소를 열고 **공유 → 홈 화면에 추가**를 선택합니다. iOS Safari는 웹페이지 안에 설치 버튼을 제공하지 않을 수 있습니다.
- **데스크톱:** 지원 브라우저에서 주소 표시줄의 설치 아이콘이나 브라우저 메뉴의 설치 항목을 선택합니다.

설치된 앱은 브라우저 창 테두리 없이 실행됩니다. 게임 진행은 로그인이나 서버가 아니라 브라우저 로컬 저장소에 저장되므로, 같은 기기·브라우저·사이트 주소에서 이어집니다.

## 오프라인 이용과 업데이트

서비스 워커가 처음 사이트를 성공적으로 열 때 앱 화면, manifest와 아이콘을 캐시합니다. 이후에는 이미 방문한 사이트를 오프라인으로 열 수 있습니다. 게임 진행은 계속 브라우저 로컬 저장소를 사용합니다.

앱 파일을 업데이트할 때는 sw.js의 CACHE_NAME 버전 문자열을 올려 기존 브라우저 캐시를 교체합니다. Pages 배포가 끝난 뒤 앱을 다시 열면 새 파일을 가져옵니다.

## 파일 구성

- index.html: 게임 화면, 게임 규칙, 스타일, 로컬 저장과 설치 안내
- manifest.webmanifest: 설치 이름, 시작 경로, 표시 방식, 앱 아이콘
- sw.js: 앱 파일 캐시와 오프라인 진입 처리
- icons/: 홈 화면과 앱 목록에서 사용할 PNG 아이콘

별도 빌드, 서버 코드, 계정, 외부 이미지·폰트·API가 필요하지 않습니다. index.html을 파일로 직접 열어도 플레이할 수 있지만, PWA 설치와 서비스 워커 오프라인 캐시는 HTTPS로 게시한 사이트에서 사용해야 합니다.
